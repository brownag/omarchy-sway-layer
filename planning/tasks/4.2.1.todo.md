# 4.2.1 -- Opt-in installer support

## Goal
Add an install-only `--enable-bemenu-themed` flag to `bin/apply-sway-layer` that installs the existing wrapper to the user bin dir, rewrites the *copied* SUPER+D binding, warns when the bin dir is off `PATH`, is previewed under `--dry-run`, removed on `--uninstall`, and is snapshotted/restored by `scripts/backup.sh` + `--rollback`.

## Notes
- `--enable-bemenu-themed` is install-only; the guard generalizes the existing `[[ $ACTION == install || $ENABLE_WAYBAR == 0 ]]` line.
- `binds_sway.lua` is installed as `$CONFIG_HOME/hypr/sway_bindings.lua`; rewrite the copied target only. Source `config/**` and `scripts/bemenu-themed` are untouched.
- Default install (flag absent) must be byte-identical to today: no wrapper, binding stays `bemenu-run`, no new warnings.
- The Makefile's `grep -Fq 'bind = SUPER, d, exec, bemenu-run' config/hypr/binds_sway.conf` assertion stays valid (source unchanged).
- Dry-run reuses the real replace helpers on temp copies so preview and install cannot drift.
- `$BIN_HOME` is a file target, not a managed directory; uninstall/rollback use `rm -f`/single-file restore, not `rm -rf` of a whole dir.
- Test already sets `XDG_CONFIG_HOME`/`HOME`; add `XDG_BIN_HOME`; `OMARCHY_SWAY_BACKUP_ROOT` is available for any backup assertions (not strictly needed here).
