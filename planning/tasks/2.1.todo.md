# 2.1 -- Main installer CLI

## Goal
Implement the scoped strict-mode Bash CLI to install, uninstall, roll back, and dry-run the managed Sway-layer configuration while preserving unrelated user configuration.

## TODO items
- [x] Create `bin/apply-sway-layer` with Bash shebang, `set -euo pipefail`, required named functions, argument parsing for all specified flags, and help/usage output.
- [x] Resolve project templates/helpers relative to the CLI path and user config paths through `XDG_CONFIG_HOME`/`HOME`; do not require root or target upstream Omarchy files.
- [x] Parse `scripts/detect_omarchy.sh`'s stable `KEY=value` output and use its config/Lua/bar/runtime facts to choose plain-conf or Lua integration and reload behavior.
- [x] Implement default install so it invokes `scripts/backup.sh` before any target mutation, then copies Hyprland bindings, Lua bindings, Waybar config/CSS, and the minimal Quickshell override to their specified managed destinations.
- [x] Idempotently add the managed `source = ~/.config/hypr/binds_sway.conf` line to `user_custom.conf` when present, otherwise to `hyprland.conf`, preserving all existing contents and other lines.
- [x] For Lua-engine detection, install `sway_bindings.lua` and idempotently add `pcall(require, "sway_bindings")` to existing `bindings.lua`; if only `looknfeel.lua` exists, create `bindings.lua` with the integration line.
- [x] Make `--enable-waybar` idempotently add the specified managed Waybar `exec-once` line; default install must not add it or disable Quickshell.
- [x] Implement `--uninstall` to remove only managed files/lines, and `--rollback latest|TIMESTAMP` to restore the chosen backup snapshot using its manifest, without replacing unrelated files or touching upstream paths.
- [x] Make `-n`/`--dry-run` report exact planned file changes/actions without writing, including no backup creation or config-directory mutation; keep option validation and errors clear.
- [x] Attempt Hyprland reload and Waybar signal/restart best-effort only when appropriate under a live session; runtime failures must not fail an otherwise successful install.
- [x] Run the acceptance checks: `bash -n bin/apply-sway-layer`; greps for `install_layer()`, `rollback_layer()`, and `DRY_RUN=`; and, if practical, a dry-run smoke test with a temporary `HOME`.

## Notes
Analysis references: Task 2.1 and its constraints/acceptance command in `planning/EXECUTION_PLAN_1.md`; dependency reports for 1.1/1.2 in `planning/STATE_1.md`; and the actual helpers/templates. `detect_omarchy.sh` emits booleans as stable `KEY=value` lines, uses `${XDG_CONFIG_HOME:-$HOME/.config}`, scans config for Quickshell/Waybar launch strings, and reports runtime command availability. `backup.sh` creates a collision-safe timestamped snapshot beneath `OMARCHY_SWAY_BACKUP_ROOT` or the config home, copies `hypr`, `waybar`, and `quickshell` trees when present, writes `manifest.txt`, and prints the backup directory. Static templates are `config/hypr/binds_sway.conf`, `binds_sway.lua`, `config/waybar/config.jsonc`, `style.css`, and minimal `config/quickshell/BarOverrides.qml`. The Lua template returns a binding table; dependency report notes that no Omarchy consumer API is specified, while Task 2.1 explicitly requires the `pcall(require, "sway_bindings")` integration. Keep all implementation changes confined to `bin/apply-sway-layer` (and its `bin/` parent); do not run install actions against the real home or change any existing files.
